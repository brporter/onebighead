A: Refined Compact List

Fix the current tree design. Collapse toggle moves into the header. Indentation is tight (24px per level instead of 22px+18px base). Names truncate with ellipsis instead of wrapping. Child dots are smaller. No toggle spacer for leaves — saves horizontal space. The tree stays structurally similar but works within the sidebar width.

Strengths

  • Minimal change, fixes the actual problems
  • Familiar tree pattern — no learning curve
  • Scales to deep nesting with truncation

Tradeoffs

  • Deep nesting still compresses names
  • Static — no interactive delight

B: Drill-Down Navigation

Replace the tree entirely with a single-level list that drills into children. Clicking a category with subcategories "navigates into" it — showing its children as a flat list with a breadcrumb trail and back button. Each item gets the full sidebar width. Deep nesting is handled by depth, not indentation.

Strengths

  • Every category name gets full width — no truncation ever
  • Handles unlimited depth elegantly
  • Room for item counts and descriptions
  • Animated transitions between levels add energy

Tradeoffs

  • Can't see the full tree at once
  • More clicks to reach deep categories
  • Unfamiliar pattern — some learning curve

C: Accent Bar Accordion

Root categories are accordion sections separated by dividers, each with a vertical accent color bar (gradient ribbon turned 90°). Expanding a section reveals children as a compact nested list. The accent bar replaces the dot as the color indicator — more visible and more distinctive. Item counts and subcategory counts shown on each section header.

Strengths

  • Stronger visual identity than dot-based tree
  • Richer information density (counts, sub-counts)
  • Full width for names at root level
  • Children are compact and tight
  • Accordion animation adds subtle energy

Tradeoffs

  • Deep nesting (3+ levels) still needs indentation within sections
  • More vertical space per root category

All three fix the current problems: collapse button integrated into header, no text wrapping. They differ in how they handle hierarchy, information density, and visual identity. You can also mix elements — e.g., the accent bar from C with the compact list structure of A.
