Design Section 4: State Management

How state changes drive the UI across all views

State Variables in CategoryManagerModal

State Overview
NEW STATE
view: 'tree' | 'form'
Controls slide position. Defaults to 'tree'.
NEW STATE
showQuickCreate: boolean
Controls popover visibility. Defaults to false.
NEW STATE
quickCreateName: string
Name entered in popover, passed to form on "More Details".
KEPT
selectedCategoryId: number | null
Which category is being edited. Set on row click.
KEPT
isNew: boolean
Create vs edit mode. Set on "More Details" or quick create → form.
KEPT
formHasChanges: boolean
Drives discard confirmation for back/cancel/close.
REMOVED
auto-select on open
No longer auto-selects first category. Modal opens to tree view.
KEPT
showDeleteConfirm, showCancelConfirm, etc.
All confirmation modal states unchanged.

State Transitions

State Machine
view = 'tree'
Click category row → selectedCategoryId = id, isNew = false, view = 'form'
Click + button → showQuickCreate = true
Drag & drop → reorder/reparent API call, reload (stays on tree)
Click × close → close modal
showQuickCreate = true (popover over tree)
Save → API create, reload, showQuickCreate = false, stay on tree
More Details → showQuickCreate = false, isNew = true, selectedCategoryId = null, view = 'form'
Cancel / click outside → showQuickCreate = false, quickCreateName = ''
view = 'form'
← Back (no changes) → view = 'tree', selectedCategoryId = null
← Back (has changes) → show discard confirm → view = 'tree', selectedCategoryId = null
Save / Create → API call, reload, view = 'tree', selectedCategoryId = null
Delete (confirm) → API delete, reload, view = 'tree', selectedCategoryId = null
× close (has changes) → show discard confirm → view = 'tree'

Modal Open/Reset

When the modal opens, all state resets to defaults:
view = 'tree', selectedCategoryId = null, isNew = false, formHasChanges = false, showQuickCreate = false, quickCreateName = ''

Categories load fresh from API. Tree view is shown immediately — no auto-selection.
