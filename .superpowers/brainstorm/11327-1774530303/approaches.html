Category Manager — Approach Options

How should the two-panel Category Manager be structured?

A

Side-by-Side Panels (Recommended)

Tree on the left (~35%), edit form on the right (~65%). Tree stays visible at all times. Selecting a category loads its details into the right panel. Add/delete/sort actions live in a toolbar above the tree. Drag-and-drop reorder in the tree panel.

Pros

  • Full tree always visible — easy to see context and hierarchy
  • Familiar pattern (file explorer, settings panels)
  • Drag-and-drop works naturally in a persistent tree
  • Edit form has plenty of room

Cons

  • Needs a wider modal (~800px+) to fit both panels
  • On small screens, panels may need to stack vertically
B

Slide-Over Detail

Full-width tree list as the default view. Clicking a category slides in an edit panel from the right, overlaying part of the tree. A back arrow returns to the full tree view. Feels like a mobile navigation pattern.

Pros

  • Tree gets full width when browsing
  • Works well on smaller screens
  • Clear "browse vs. edit" mode separation

Cons

  • Loses tree context while editing — can't see hierarchy
  • Extra navigation step to go back and forth
  • Drag-and-drop only available in browse mode
C

Expandable Inline Rows

Tree list where clicking a category expands an edit form inline, directly below the row. Other categories remain visible above and below. Collapse one to edit another.

Pros

  • No panel split — simple single-column layout
  • Edit form stays near the category it belongs to

Cons

  • Expanded form pushes other categories off-screen
  • Drag-and-drop becomes awkward with expanded sections
  • Cramped form layout in a narrow column
  • Visual noise — hard to distinguish editing from browsing
